# Session startup and token admission (#0125)

The fixed native `imageinfo session read` transport retains the boundary frozen
in [#0121's inventory](native-token-inventory.md). It does not implement the
MAP-023 upstream persistent-option protocol. The existing
[#0116 startup and pipe tests](read-session-process.md) remain the framing,
lifecycle and recursive-operation evidence; #0125 adds exactly **18** finite
token cells in [two actual-process tests](../../tests/cli_session_admission.rs).
The tests share #0116's unchanged bounded process harness, now extracted to
[`session_process.rs`](../../tests/support/session_process.rs).

## Explicit dispositions

| Form | Current native disposition |
| --- | --- |
| `-stay_open True` | Unsupported argv option at session startup and inside a metadata-read request; no persistent setting or legacy ready marker. |
| `-execute` | Unsupported argv option at startup and in a read request; JSONL framing dispatches requests instead. Numbered variants remain unqualified. |
| `-common_args` | Unsupported argv option at startup and in a read request; no inherited common token state. |
| Request tokens `["session", "read"]` | Existing #0116 actual-process cell yields request status 2, `REQUEST_OPERATION_UNSUPPORTED`; the session continues and a later ordinary read succeeds. It cannot start a recursive session. |
| Literal `-stay_open`, `--output=json` or `session read` after metadata-read `--` | One filename token, independently witnessed by the selected authored file's distinct firmware value. A token containing a space is not split into commands. |
| Startup operands after `--` | No operands are admitted by `session read`; the tested literal operands yield status 2, `INVALID_COMMAND`, rather than becoming request tokens. |

These are current unsupported/different dispositions, not adopted compatibility
differences, parity acceptance or an exhaustive option/value survey. MAP-023 and
the wider #0015/#0141 residuals remain. The pinned reference inventory supplies
the spellings; no reference executable comparison is claimed.

## Added finite cells

| Cells | Actual executable observation |
| --- | --- |
| Startup 1–3 | Each of the three legacy options refuses with `INVALID_OPTION`, with the explicit JSON selector in three different argv positions. |
| Startup 4 | `--color` at root and read scopes refuses as a duplicate. |
| Startup 5–6 | Protected startup operands `-stay_open` and `session read` refuse with `INVALID_COMMAND`. |
| Request 1–3 | The three legacy options refuse with `INVALID_OPTION`; no file results or artifacts. |
| Request 4 | Root color, metadata-scope noninteractive preference and read-scope selector admit one selected authored read. |
| Request 5 | An operand before `--tag`/`--values=all` still selects one occurrence and enables its display representation. |
| Request 6–7 | Cross-scope duplicate color and same-scope duplicate values refuse. |
| Request 8 | Repeating the same selector emits its one matching occurrence once. |
| Request 9 | Repeating the same pathname reads it once and reports one deduplicated input. |
| Request 10–12 | The three literal filenames above read their distinct expected authored values. |

Startup tests retain open stdin, require process status 2, a single ordinary CLI
JSON error envelope, nonempty stderr, no protocol prefix, no file results and no
artifacts. Startup refuses without waiting for request input. Source inspection
of `main`'s parse-result branches and `cli::parse`'s I/O-free grammar establishes
why a startup grammar error cannot reach media dispatch or the session runtime.
The unchanged source-byte/property inventory alone would not prove absence of a
read. The prior #0116 tests retain plain-error, help/version and selector routing.

Request cells use one real child process and OS pipes. They wait for ready,
send one frame, receive its complete result before sending the next, and finish
with a successful explicit close and process status 0. Expected statuses, error
codes, paths, selected occurrence count, value witnesses and deduplication counts
are stated independently in the test; results are not generated by calling the
same request implementation as an oracle. All authored files have their complete
bytes, last-write timestamp and readonly flag compared before/after, with the
exact directory inventory retained. This is not a claim about access timestamps
or every filesystem property.

## Verification and limits

The Windows development run passed all **14 tests** across `cli_session_startup`,
`cli_read_session` and `cli_session_admission`: four existing startup tests,
eight existing pipe tests and two new tests containing the 18 cells. Reproduce:

```text
cargo test --locked --test cli_session_startup --test cli_read_session --test cli_session_admission
```

The shared extraction changes test harness location and visibility only; it adds
no runtime, parser, queue, cancellation, deadline, persistent setting, dependency
or native API. Watchdogs and capture limits belong to the test harness. This
finite authored qualification supplies no camera outcome, RAW mutation,
publication/storage authority or broader legacy-session compatibility.
