# Finite P0 R5 assertion gaps

Revision `2026-10-15.1`, #0071. The
[versioned ledger](p0-assertion-gaps.v1.json) joins the original
[29 fixture families](case-plan.v1.json) to current native read, preview and
read-only admission evidence. It selects five precise next assertions rather than
requesting a larger general corpus. This is an evidence/work ledger, not a new
capability, fixture admission, photo request or release gate.

## Read the evidence correctly

The original plan's `not-collected`/`specified-not-executed` fields describe its
2026-10-10 planning state. They are not rewritten into present execution claims.
This new ledger retains every original family ID and priority and gives each a
current scoped disposition. Original P1/P2 camera variation, GPS/workflow breadth,
C-RAW and Dual Pixel RAW are not promoted to first-full-RAW P0 requirements.

The [published native read evidence](../reader/validation.md) supports the declared
field/profile subset in its narrow published stratum. Public authored controls
exercise additional structural/endian/error shapes; they are not camera setting
coverage. [JSON boundary qualification](../legacy-compatibility/native-read-json.md)
adds exact serialization/evidence about authored CLI records, not new input formats.
Correct [admission refusals](../write-safety/write-admission.md) are evidence of
those refusals, not positive RAW mutation support.

Evidence classes are explicit:

| Class | What it can support |
| --- | --- |
| `native-authored` | Actual root behavior on publicly authored structural/value cases. |
| `published-private-summary` | Only facts already published in the cited historical summary, with its limits. It supplies no future publication permission. |
| `research-authored` | The named research/model/component controls, without root-feature or camera-coverage promotion. |
| `method-only` | Method and scope only. It supplies no public camera outcome, count or denominator. |
| `requirements` | Obligations or implemented scope declarations; not proof that an experiment ran. |

In particular, the public #0099/#0102 documents remain method-only here. New
camera-derived results from those private experiments are not imported, summarized
or counted by this ledger. Its five assertion rows were uncovered named deltas
when revision `2026-10-15.1` selected them; their `alreadyCovered` text records that
checkpoint. Subsequent [#0072 authored evidence](alias-boundary-family.md) qualifies
the narrow P0A-001 interval distinction on sixteen cases. The other four targeted
needs remain open. The versioned selection ledger and original family plan are
preserved as historical inputs, rather than rewritten into broader format coverage.

The rank-1 need does not duplicate the already tested exact decoded/undecoded

The rank-3 need is specifically an asserted disagreeing **cross-origin** pair.

There is no newly nominated P0 photo-acquisition target. A different ISO/firmware/

## What remains outside these five deltas

All 29 families have a ledger row; none is silently called complete because it has
no selected assertion. `partial-current-slice` records bounded coverage, not full
family closure. For example, authored three-OS CI is not three-OS private-camera
parity, and structural recognition is not tamper-proof camera identity.

Original P0 embedded-XMP/sidecar conflict, typed XMP and sidecar writes retain
implementation prerequisites. Native explicit pairing and #0081/#0083/#0084
authored component/mapping/preservation research do not implement a root XML or
sidecar writer. Additional photos alone cannot close those feature gaps.

Original P0 actual RAW mutation faults/cancellation/recovery likewise retain the
admitted operation/profile and adapter prerequisites. Non-authorizing stale-plan
revalidation and marker research do not count as successful RAW writes. Current
native cancellation/deadline limitations are explicit; this ledger does not name
a validator as a substitute for missing cancellation infrastructure.

Existing synthetic rights/hash/phase rejection controls are evidence of those
controls, not absence of all admission evidence and not clearance of real media.
The MIT project license cannot expand a source grant. Unknown or denied assets
remain unusable for the requested phase/audience until that scope is reviewed.
No product gate is waived, and no universal hypothetical-checksum absence proof
or new hardware/power campaign is added. The accepted
[best-effort disposable-VM-off policy](../write-safety/power-test-policy.md) remains
in force.

## Rights, access and completion

Authored negative/setting cases use project-created marker/metadata bytes and can
be public. A later camera/preview validator run needs the exact admitted bytes,
reviewed tool/runtime recipe and allowed phase/decoded-derivative permission.
Do not silently upgrade a reference-only fixture to differential or modify use.
When `publishReports` is denied, all new camera-derived outputs, decoded pixels,
counts, Boolean results and reports remain private. Original/private paths,
per-image hashes and personal metadata never enter this ledger or public CI.

The [closed schema](p0-assertion-gaps.schema.json) prevents accidental fields and
unsupported evidence/access labels. The
[semantic checker](../../scripts/check_fixture_gaps.py) joins all original IDs and
priorities, requires consistent bidirectional family/assertion references and
contiguous ranks, checks public evidence paths/classes, enforces private disclosure
and separates umbrella routing from actual executable children. Its authored
negative controls test the ledger constraints; they do not execute the listed
research assertions or admit a fixture.

```text
python scripts/check_fixture_gaps.py
python scripts/check_docs.py
git diff --check
```

#0071 finishes by publishing this finite, validated prioritization and the existing
evidence/unknown/access distinctions. A selected future assertion becomes verified
only after its bounded ticket, actual execution and evidence review; it is not
verified merely because this ledger or its checker passes.
