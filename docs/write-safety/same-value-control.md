# Same-value CR3 reference-write control

Method revision `0105-same-value-control-2026-10-15.1`, #0105, advances the bounded
causal question left by [#0102 attribution](cr3-rewrite-attribution.md). The
[research package](../../experiments/0105-same-value-control/README.md) reuses the
exact frozen [#0099 reference characterization](cr3-reference-effects.md) and its
retained changed-date outputs. It issues only a new original-value assignment
into a fresh private derivative. The already retained changed-date write is never
repeated, and other tag assignments are never added to force a rewrite.

## Original-value operation and comparison

Two existing bounded readers independently locate the unique CMT2 `0x9003`
ASCII20 allocation. They must agree on its physical extent and reject aliases
or structural overlap. The bytes must encode a valid Gregorian date/time with
the existing fixed-width syntax. Pinned reference extraction, duplicate/unknown
values enabled with groups `0:1:4:5`, must independently expose exactly one
ExifIFD DateTimeOriginal matching those original bytes. The original value must
differ from the retained changed-date intent.

The exact write argv uses `-config ""`,
`-ExifIFD:DateTimeOriginal=ORIGINAL_VALUE`, and `-o FRESH_OUTPUT`, with the original
as the input. There are no overwrite/ignore-error flags. The tool identity and
surrounding recipe match #0099; only the assigned value and fresh destination
change. Every stdout/stderr capture and command result is retained, including
timeouts. A missing artifact remains a short-circuit-or-refusal observation;
successful exit alone does not establish which occurred. A partial or failed
artifact remains retained and is never treated as a completed derivative.

A completed output must retain the original physical and independently decoded
selected date. Unmodified #0102 analysis compares original/same-value,
original/changed-date and same-value/changed-date artifacts: logical allocations,
disjoint complete physical-byte partitions, unallocated CMT ranges, parsed CTBO
and sample-address relationships. Complete positional differing-run counts and
digests additionally compare original/same and same/changed bytes. No bounded
run sample is presented as complete accounting.

Identical metadata extraction records the complete source/same and same/changed
key deltas, preserving aliases and unexpected fields. The existing pinned LibRaw
tool independently unpacks only the new completed derivative; its actual marker,
termination, stderr, output artifact and full PGM hash are checked against the
bound baseline. Frozen changed-date unpack artifacts supply the third leg;
they are verified rather than regenerated. Decoder failure remains explicit.

## Classification and limits

An artifact identical to its original is a byte-identical no-op artifact. For
logical cells identified by #0102 roles, equal bytes in all three are unchanged.
A cell changed by both assignments to the same complete bytes is a
shared-rewrite observation. A cell unchanged by the original-value assignment
but changed in the frozen changed-date output is a changed-date-associated
observation. Missing relationships, different rewrites and remaining cases stay
unexplained. These are finite relationships under the exact inputs/tools; a
changed-date-associated observation is not a proof that the date caused it.

Common rewrites do not prove necessity, and unchanged bytes do not prove semantic
independence. A no-artifact short circuit cannot isolate rewrite mechanics. The
method does not force a rewrite, infer checksum/signature semantics, dismiss
unknown allocation dependencies or use reference behavior as a format standard.
Independently authored tests cover original-date extraction, aliases, invalid
dates, lineage/hash substitution, unsafe/duplicate IDs and classification cases.
The separate auditor reconstructs the private comparisons from actual artifacts.

Independent review identified an authored classifier case where two missing
candidate roles could incorrectly compare as the same bytes. The final classifier
keeps every missing source/candidate relationship unexplained, with authored
common-removal, common-addition and changed-only-removal regressions. This is an
implementation control finding, not a public camera observation. Existing media
captures retain their exact historical write-driver source. A separately frozen
read-only analysis root binds the media manifest, write-driver hash and final
classifier/reclassifier hashes, and supersedes only `cellClassification`.
Every other report field must remain exactly equal. Its independent audit checks
that explicit lineage; no reference write is repeated for a classification fix.

Existing #0099/#0102 bounds apply: at most eight admitted inputs, 256 MiB per
source/candidate, bounded box/TIFF/address inventories and 120 seconds per
external command. Eight GiB scratch availability is observed, not reserved;
there is no physical allocation quota or hard native-I/O deadline. All prior
captures and failed attempts stay retained. No source-media modification,
production writer, root SDK/dependency/unsafe change, storage admission or new
power/OS experiment is introduced. #0078 retains its full positive format and
storage acceptance, independently of this research control.
