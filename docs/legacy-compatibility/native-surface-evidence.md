## Native transport counterexample retained

[#0140](native-session-handles.md) records distinct native EOF and fault cases.
The WSL/MUSL read-only stdout case naturally returns status **0**, with no captured
stdout or stderr. Delivery is unestablished. This is neither a successful session
transcript nor an observed `OUTPUT_INCOMPLETE` result. The ledger retains this
limit under #0141's audit disclosure and #0015's remaining compatibility guarantee.
Status alone therefore cannot establish successful delivery for this case.

Invalid/closed Windows stdin and closed/write-only MUSL stdin can normalize to
EOF; those setups do not prove `INPUT_IO`. Windows write-only stdin and MUSL
directory stdin provide the separately observed native input failures. Windows
NULL stdin is watchdog-censored, with no natural outcome. Native flush-only
failure injection remains unavailable; library faulting-writer tests retain their
separate actual scope. WSL/MUSL observations do not qualify hosted GNU Linux or
macOS builds; those require their exact retained native CI artifacts.
