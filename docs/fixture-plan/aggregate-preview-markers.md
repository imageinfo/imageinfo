# Authored aggregate preview marker limit

Observed 2026-10-16, #0163, selected assertion P0A-005 under #0018.
The actual read-only native admission API refuses three project-authored stored
JPEG framing extents containing **2,000 COM markers each**, with
`LIMIT_EXCEEDED: JPEG marker limit exceeded`. Each extent is individually below
4,096 counted markers. The combined input contains 6,000 COM markers; counting
each extent's terminal EOI gives 6,003 counter events. SOI is consumed separately.

The [integration tests](../../tests/aggregate_preview_markers.rs) and public
[recipe/results](aggregate-preview-markers.v1.json) retain exact generated bytes
and expected outcomes through a reproducible authored recipe. The existing
[container builder](../../tests/support/mod.rs) wraps three distinct extents as
thumbnail, preview and JPEG track. No camera media or private outcomes are used.

## Independent input checks

Each extent is exactly `FF D8`, numbered COM segments, then `FF D9`, with no
padding. Each COM segment is `FF FE 00 05 RR IIII`: `RR` identifies resource 1,
2 or 3, and `IIII` is its zero-based big-endian uint16 ordinal. A 2,000-COM
extent therefore occupies exactly 14,004 bytes. This is bounded JPEG marker
framing, without a claim of a decodable image or complete JPEG codestream.

A separate narrow oracle walks those exact stored bytes, checks declared segment
lengths, identifiers and consecutive ordinals, requires terminal EOI at the exact
extent end, and counts each resource independently. It does not call or derive its
expectations from the production marker scanner. Actual reader-selected ranges
must match each distinct authored extent exactly once. Deliberate SOI, marker,
length, ordinal, EOI and truncation errors fail this oracle. An earlier malformed
envelope therefore cannot satisfy the aggregate-limit assertion.

## Actual observations

Three focused tests pass, including ten file-backed native admission calls:

| COM counts across three extents | Full counter total | Native result |
| --- | --- | --- |
| 1 / 1 / 1 | 6 | Completed assessment |
| 1,000 / 1,000 / 1,000 | 3,003 | Completed assessment |
| 2,000 / 1 / 1; 1 / 2,000 / 1; 1 / 1 / 2,000 | 2,005 each | Completed assessments |
| 1,365 / 1,365 / 1,363 | 4,096 | Completed assessment |
| 1,365 / 1,365 / 1,364 | 4,097 | `LIMIT_EXCEEDED` |
| 2,000 / 2,000 / 2,000 | 6,003 | `LIMIT_EXCEEDED` |

The over-limit calls return `Err` rather than an `Assessment`. These scans are
explicitly incomplete: their full counter totals describe independently enumerated
input events, not completed scanner work. No partial findings, empty findings,
completed assessment or known authenticity absence are inferred from those errors.
The logical aggregate bound is exercised before all three extents can finish.

The six ordinary completed assessments retain `OPAQUE_DEPENDENCY_UNPROVEN` and
`production_mutation_allowed() == false`. Two additional minimal/below-aggregate
controls combine unverified firmware, a stale expected occurrence and a structural
C2PA UUID indicator. They retain the exact same four refusal codes, the known
structure finding and opaque-region count. Neither increasing benign COM counts
nor successful bounded scanning clears any of those independent refusals.

Every native admission call reads an ordinary file opened for reading. Its source
bytes, physical identity, length, readonly attribute and modification time match
before/after. Creation time is compared where the platform exposes it; absence
of that metadata is not a preservation qualification. Its directory retains exactly
the single test-created input, with no additional artifacts. The API has no
artifact-result channel or output request. Test-harness setup and teardown are
separate from the measured admission call.
